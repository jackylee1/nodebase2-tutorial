## Phase 2: Database Integration (Prisma) / 数据库集成 (Prisma)

### 1. `prisma generate` Error: `datasource.url` not supported
**Error / 错误**:
`The datasource property url is no longer supported in schema files.` (Prisma 7+)
**Cause / 原因**:
Prisma 7 changed how connection strings are handled in `schema.prisma` when using the default driver.
Prisma 7 更改了在使用默认驱动程序时 `schema.prisma` 中处理连接字符串的方式。
**Solution / 解决方案**:
- Removed `url` from `datasource` block in `prisma/schema.prisma`.
- 从 `prisma/schema.prisma` 的 `datasource` 块中删除了 `url`。
- Configured `DATABASE_URL` in `prisma.config.ts` (for migration/CLI tools).
- 在 `prisma.config.ts` 中配置了 `DATABASE_URL`（用于迁移/CLI 工具）。

### 2. `PrismaClient` Constructor Error: `datasourceUrl` / `datasources`
**Error / 错误**:
`Unknown property datasourceUrl provided to PrismaClient constructor.`
`Unknown property datasources provided to PrismaClient constructor.`
**Cause / 原因**:
The generated Prisma Client (v7) with `driverAdapter` enabled (implicitly or explicitly via schema changes) does not accept legacy connection overrides in the constructor in the same way.
生成的 Prisma Client (v7) 在启用 `driverAdapter`（隐式或通过架构更改显式启用）时，不再以相同的方式接受构造函数中的旧版连接覆盖。
**Solution / 解决方案**:
- We initially tried to pass the URL directly, but it failed.
- 我们最初尝试直接传递 URL，但失败了。

### 3. `PrismaClient` Error: Missing Adapter
**Error / 错误**:
`Using engine type "client" requires either "adapter" or "accelerateUrl" to be provided to PrismaClient constructor.`
**Cause / 原因**:
When `datasource.url` is omitted from the schema, Prisma Client expects a Driver Adapter (e.g., for Serverless/Edge compatibility) or an Accelerate URL.
当架构中省略 `datasource.url` 时，Prisma Client 需要驱动程序适配器（例如，用于无服务器/边缘兼容性）或 Accelerate URL。
**Solution / 解决方案**:
- Installed `pg` and `@prisma/adapter-pg`.
- 安装了 `pg` 和 `@prisma/adapter-pg`。
- Updated `src/lib/db.ts` to use `PrismaPg` adapter.
- 更新 `src/lib/db.ts` 以使用 `PrismaPg` 适配器。

```typescript
import { PrismaClient } from "@prisma/client";
import { PrismaPg } from "@prisma/adapter-pg";
import { Pool } from "pg";

const connectionString = process.env.DATABASE_URL;
const pool = new Pool({ connectionString });
const adapter = new PrismaPg(pool);

export const prisma = new PrismaClient({ adapter });
```

## Phase 3: Authentication & API / 认证与 API

### 1. tRPC `Headers` Type Mismatch
**Error / 错误**:
`Argument of type 'Headers' is not assignable to parameter of type 'IncomingHttpHeaders'.` in `src/server/api/trpc.ts`.
**Cause / 原因**:
Used `fromNodeHeaders` (which expects Node.js `http` headers) on a Web Standard `Headers` object provided by Next.js App Router.
在 Next.js App Router 提供的 Web 标准 `Headers` 对象上使用了 `fromNodeHeaders`（它需要 Node.js `http` 标头）。
**Solution / 解决方案**:
- Removed `fromNodeHeaders` utility.
- Passed `headers` directly (or converted to plain object if needed).
- 删除了 `fromNodeHeaders` 工具。
- 直接传递 `headers`（如果需要，则转换为普通对象）。

### 2. Missing tRPC Packages (500 Error on Main Page)
**Error / 错误**:
`Module not found: Can't resolve '@trpc/react-query'` — HTTP 500 on all pages.
**Cause / 原因**:
The `npm install @trpc/server @trpc/client @trpc/react-query @tanstack/react-query zod` command was cancelled during execution, so the packages were never added to `package.json` or `node_modules`.
`npm install` 命令在执行过程中被取消，因此包从未添加到 `package.json` 或 `node_modules`。
**Solution / 解决方案**:
- Re-ran the install command successfully.
- 成功重新运行了安装命令。

### 3. Unused `fromNodeHeaders` import
**Error / 错误**:
`fromNodeHeaders` was still imported in `src/server/api/trpc.ts` but no longer used.
**Cause / 原因**:
The import was left behind after fixing Issue #1.
修复问题 #1 后遗留了导入。
**Solution / 解决方案**:
- Removed the unused import line.
- 删除了未使用的导入行。
